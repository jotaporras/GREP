# e22 — GEGRv2 port: the `greg` arm (2026-11-05)

**Status:** code written and unit-tested on the Mac (`tests/test_hop_table_mask.py`,
23 tests). No job submitted. JP decides the first cell.

**What:** a new e22 arm, `greg`, that ports three GEGRv2 settings into GREP's
`learnable_graph_mask` architecture. JP's instruction (2026-11-05): match the
attention mask, the write scope (dense layers on Gemma) and the write source
(the fewest taps that tie GEGRv2's full write); keep Ψ, the curriculum and the base
model as they are.

GEGRv2 names: e028 = the "GREG" full chain (`hada_warm`, 2026-09-21); e033 =
the fusion-vs-RPE ablation (2026-10-09 to 10-16); `fusion_rpearl` = e033's residual
write from the bare R-PEARL encoding alone, which ties the e028 four-tap write
(Erdős 0.778 vs 0.771).

## The three changes

| axis | e22 `hop_depth` (unchanged, the control) | e22 `greg` (new) | GEGRv2 source |
|---|---|---|---|
| mask values | log-gate `log(α + (1−α)·cos(Ψ_i, Ψ_j))`, k = 1, α = 0 | learnable additive level per hop distance 0..3 (`mask_form=hop_table`, `mask_k_hops=3`), hard block beyond | e028 `TABLE` = `mask.learnable=false graded=true k_hops=3` |
| mask layers | Gemma dense (10 global layers) | Gemma dense (same) | GEGRv2: all 28 Qwen layers |
| write layers | `dense_top_half` (last 5 globals) | `dense` (all 10 globals) | `top_half` (14 of 28) |
| write source | 4 taps (R-PEARL + 3 GT blocks) | R-PEARL tap alone (`post_fusion_hop_taps=first`) | e033 `fusion_rpearl` |
| decision rows (e18-A) | on, gain 3.0 | off (`greg`); `greg_a` keeps them | GEGRv2 has none |

Unchanged in `greg`: Ψ tower and its e13 navigator-GT weights, `structural_lr_mult`
0.012, stage-1 LoRA warm start, geo_v1 corpus, 4 epochs, lr 2.5e-4, route_only,
`decode_consistent` injection, no edge list in the prompt.

Level init follows GEGRv2's default, `[α] + [α·0.5^h]` with α = 0.7:

| hop | 0 | 1 | 2 | 3 | ≥ 4 |
|---|---|---|---|---|---|
| init | 0.7 | 0.7 | 0.35 | 0.175 | blocked |
| e028 end state | 0.45 | 1.6 | −0.24 | −0.65 | blocked |

The levels train at base LR (2.5e-4), through `_fusion_scalars`, like the post-fusion
gates. GEGRv2's own multiplier for the table is not recorded in its configs, so this
is my choice, not a match.

## Consequences

- **Ψ leaves the mask.** In `hop_table` form the mask does not call `pe_model`.
  The only route from Ψ into the LLM is the write. This is the GEGRv2 arrangement
  (e033: the write carries the whole lead over the table; q,k routes train to zero).
- **The GT blocks of the Ψ tower get no gradient in `greg`.** The write reads tap 0
  (the R-PEARL output), so blocks 1-3 are dead weight. They stay loaded for
  checkpoint compatibility.
- **Memory is unchanged.** The hop table is still a dense `[B, 1, L, L]` bias on the
  eager attention path, so the e22 OOM pattern (multi-turn prompt growth × L²) is
  the same as for `hop_depth`. The e22 eval fixes are a separate decision.
- **Checkpoints:** `gnn_weights.pt` gains `mask_level`; the loader fails loud if a
  `mask_form=hop_table` config is reloaded without it. `psi`-form checkpoints are
  untouched (the default construction has no `mask_level` parameter, test
  `test_psi_form_is_unchanged_by_the_new_kwargs`).
- **W&B:** `e22/mask_level_{0..3}` per logging step, next to the e19 `pf_*` gates.

## Open points for JP

- Mask layers: GEGRv2 masks every layer; `greg` masks the 10 dense layers only
  (Gemma's sliding layers see a 512-token window, and the decode injector only
  carries dense layers). `gnn.mask_layer_scope=all` is available if you want the
  literal match.
- Decision rows: `greg` drops them to match GEGRv2; `greg_a` is the one-flag variant
  that keeps the e18-A rows.
- The R-PEARL tap of the e13 navigator tower was trained only as an intermediate
  of that tower. GEGRv2's `fusion_rpearl` used an R-PEARL pre-trained on edge and
  hop prediction. JP: "Psi: this is fine."
